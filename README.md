# Chem-E-Car Reveiw System

Chem-E-Car 赛事资料收集、EDP 审核与团队证书制作系统。

本仓库仅包含可编辑源码、必要的空白 Excel 模板和合成测试文件，不包含真实参赛材料、报名数据、邮箱凭据或运行数据库。云端接手步骤见 [云端开发与发布](docs/云端开发与发布.md)，代码导航见 [源码结构与修改说明](docs/源码结构与修改说明.md)。

这是面向赛事工作人员的共享采集与审核站点。站点以一套独立共享密码保护，文件、设置、审核记录和导出结果保存在云端，同一密码登录的电脑与手机看到相同内容。

## 七个工作区

1. **报名表统计**：从凡科增量收集报名表，校验有效信息、人数和必填项，生成报名回执并更新唯一统计表。
2. **EDP 提交统计**：从凡科增量收集 EDP 压缩包，按第 1–5 次提交规则检查 PDF 数量与格式并生成回执。
3. **EDP 审核**：对每校最新且提交成功的 EDP 执行严格审核、记录证据、人工确认并生成双工作表 Excel。
4. **阿里邮箱连接**：管理邮箱连接状态、浏览器助手、待确认附件和高级记录。
5. **海报收集**：从阿里邮箱收取 AI、JPG、JPEG、ZIP、7z、RAR，单文件上限 200MB。
6. **视频收集**：从阿里邮箱收取 MP4、ZIP、7z、RAR，单文件上限 200MB。
7. **证书制作**：保存可复用的证书模板，并在浏览器本地生成和下载单张获奖证书 PDF。

## 文件来源与浏览器要求

- **凡科只负责报名表和 EDP**。使用电脑端 Edge 或 Chrome 安装 `chemecar-fanke-helper.zip`，在同一浏览器登录凡科和本站即可；不需要开通“数据推送”，也不必手动进入表单第一页。
- **阿里邮箱只负责海报和视频附件，并协助写入报名表/EDP 回执草稿**。在同一浏览器登录阿里邮箱和本站即可；助手会自行进入所需页面，不要求人工刷新或停留在收件箱、写信页。
- 浏览器采集依赖电脑端扩展。电脑关闭、浏览器退出、账号退出登录或电脑休眠时会暂停；重新打开并保持登录后继续。
- 手机可以登录站点查看共享记录、下载文件和处理审核，但不能安装桌面浏览器扩展，因此不能直接发起依赖扩展的凡科/阿里邮箱扫描。

## 增量收集规则

- 报名表、EDP、海报和视频分别保存自己的起始日期；扫描只处理该日期及之后、且属于当前栏目的文件。
- 同一学校按**提交时间最晚**的合格版本为准，校区名称保持独立；学院、系等多余后缀会在不混淆学校的前提下规范化。
- 云端已有且内容未变化的文件跳过；新文件或内容变化文件更新。
- 用户从共享云端删除后，再次增量收集会检查云端是否仍存在该文件；缺失的文件会重新收集，不会因历史上下载过而永久跳过。
- 不确定的压缩包或附件进入“待确认/异常”清单，不会静默归入错误栏目。

## EDP 提交与回执

- EDP 支持 ZIP、7z、RAR；压缩包可以先包含一个学校目录，PDF 位于该目录内也会递归识别。
- 第 1 次提交要求 3 个 PDF：中文版 EDP、英文版 EDP、EDP 增补文件。
- 第 2–5 次提交要求 4 个 PDF：前三项加 MOC。
- 系统综合文件名和 PDF 首页证据识别四类文件，不要求每个文件名都完整包含“EDP”。
- 压缩包可额外包含一份同校 XLSX 随包报名表。该文件不计入 EDP 文件数；提交时间较新且内容有效时，会按独立报名表相同规则更新报名表栏目和唯一统计表。无效或较旧的随包报名表只显示联动结果，不改变 EDP 合格结论。
- 加密压缩包、损坏压缩包、路径不安全或超出解压安全上限的文件会被拒绝，并明确列出原因。
- 回执收件邮箱取自同校最新报名表；缺少有效邮箱的学校会跳过并继续处理后面的学校。
- 助手只把收件人、主题和正文分别写入阿里邮箱草稿，并逐项回读确认；**不会自动发送邮件**。

## EDP 审核与 Excel

- 审核只针对每校最新、已通过提交包检查的 EDP。每次重新提交都会保留旧审核历史，新版成为当前审核对象。
- 自动判定只能依据 EDP 中可定位的明确证据。每项状态仅为：**是、否、不适用、待人工确认**；证据缺失、矛盾、图像不清或无法可靠解析时必须标为“待人工确认”，不能猜测。
- 审核内容按“首页与报名信息、工作安全评估、标准安全操作、近五年方案、其他规则”分组。首页只检查学校、队长、指导教师、队名、两类邮箱、Revision 和 Revision Date；`OnsiteSafetyJudge`、`OnsiteTrackLength`、`OnsiteTrackWidth` 不参与审核。
- 审核详情为只读预览，显示结论、文件名、页码和原文摘录；不要求操作员逐条点保存。原有人工覆盖与定稿接口保留，已有覆盖记录不丢失。
- 小车完整照片当前标为“暂缓审核/不阻塞定稿”，不会阻止正式文件生成；待以后提供照片专项标准后再升级审核规则。
- **草稿 Excel** 可以在存在“待人工确认”时生成，用于继续人工审核；文件中会明确保留待确认状态。
- **正式 Excel** 只有在所有“阻塞定稿”的待确认项已处理并完成最终确认后才能生成；非阻塞提示可以继续保留。
- 每所学校各有一份 Excel，严格保留模板中的两个工作表：`1) EDP Cover Page` 和 `2) EDP Evaluation`。模板示例学校、姓名、邮箱和旧意见不会带入新文件。
- 如果合格 EDP 已存在但审核清单缺失，点击“同步并刷新审核任务”。同步只补建缺失任务，不重复创建、不重置已开始或已完成任务；某个历史学校无法推断轮次时会单独显示，其他学校仍继续补建。
- 审核意见表只有竞赛年份可编辑；安全与规则审查人潘芳丽、安全与规则审查人邮箱 `service@chemecar.cn` 和专家组成员华炜由系统固定写入，专家邮箱保持空白。

## 年度 EDP 规则如何更新

1. 打开“EDP 审核”，在最上方“年度竞赛规则”填写适用年份并上传当年的规则 PDF（最大 50MB）。
2. 系统先保存为候选版本，显示正文检测年份、解析警告、候选规则事实、证据页码以及与当前版本的变化摘要；此时不会改变任何正式审核。
3. 操作者核对候选内容后点击“确认并启用”。若填写年份与正文年份冲突，界面会再次提示，必须明确确认后才能启用。
4. 同一年度启用新版本后，旧版本会转为历史归档。旧审核任务和旧 Excel 始终锁定原规则版本，不会被新文件静默改写。
5. 对历史任务可选择“按已锁定规则重新审核”；如需采用刚启用的规则，点击“按当前启用规则另建复核”，系统保留原任务并新建可追溯的复核任务。
6. 原规则 PDF 可随时下载；只有尚未启用、未被审核引用的候选或失败版本可以删除。

年度规则抽取用于发现客观、可定位的要求，不等同于自动理解整份规则。系统无法可靠判断的内容仍进入“待人工确认”，不会仅因关键词缺失就自动判定不合格。

## 文件在哪里、如何下载和删除

- 收集后的真实文件位于本站共享云端，不会自动进入当前电脑。
- 在对应工作区的“每校最新版本/合格文件/最新海报/最新视频/审核导出”清单中点击“保存到本地”或“下载 Excel”，文件会进入浏览器设置的下载文件夹。
- 单个文件可点击“删除”并二次确认；多个文件可勾选后批量删除。删除会影响所有共享用户，但不删除凡科源记录或阿里邮箱原邮件。
- 删除后的凡科报名表或 EDP 可由下一次增量扫描恢复；邮箱附件若源邮件仍在且扫描检查点允许，也可重新归档。

## 邮箱安全边界

- 浏览器助手不读取、保存或上传凡科/阿里邮箱登录密码、Cookie。
- 助手读取允许类型的附件并保存经过确认的草稿；不会自动发送邮件，也**不会删除、移动或标记原邮件**。
- EDP 首页的队长邮箱、指导教师邮箱只用于完整性审核，绝不作为回执收件人；回执只能使用同校最新版报名表中已经提取并验证的邮箱。
- 无法确认收件人、主题或正文已正确写入时，不保存空草稿，并跳过当前学校继续处理后续学校。

## 证书制作与隐私边界

1. 打开“07 证书制作”后，首次填写并保存**赛事名称、落款文字和公章图片**。这些内容是可复用模板；公章只应使用获准的正式文件，测试时请使用非生产测试章。
2. 之后每张证书只需填写学校、奖项、指导教师和参赛队员，以及颁发月份。竞赛年份由“EDP 审核”中的年度竞赛设置提供，不能在证书页面单独修改。
3. 单张证书最多可列出 5 名指导教师和 15 名参赛队员。证书 PDF 在浏览器本地生成；学校、奖项、指导教师和参赛队员等本次证书信息仅在浏览器本地处理，不会上传，也不会保存证书历史。
4. 当前仅支持逐张生成，不支持批量生成或证书历史管理。本站只生成供操作者检查和下载的草稿文件，不会自动发送邮件或公开发布证书。清空本次证书信息会移除当前页面的填写内容和生成结果。

## 本地开发与验证（方案 A）

从 VS Code 打开 `Chem-E-Car.code-workspace`，首次在终端执行 `npm run local:setup`，然后按 F5。详细说明见 [VS Code 运行指南](docs/VSCode运行指南.md) 与 [源码结构与修改说明](docs/源码结构与修改说明.md)。

方案 A 保留 React/TypeScript 界面和云端适配，将确定性判定迁入本项目 C++17/WASM 核心，压缩包解压使用 7-Zip C++/WASM。**这不是全站纯 C++ 重写**；浏览器交互、PDF 文字提取、Excel 模板写入仍由现有 JavaScript 库负责。

合格 EDP 入库后自动排队审核，操作员先预览，再按需下载单个 Excel 或批量 ZIP。下载只读取已保存结果，不重新审核。时区固定北京时间，栏目起始日期修改后自动保存。

要求 Node.js `>=22.13.0`。

```bash
npm run local:setup
npm run dev
npm test
npm run lint
npm run build
```

- `npm test`：执行生产构建和完整功能回归。
- `npm run lint`：检查 TypeScript、React 与无障碍规则。
- `npm run build`：生成可供 Sites 托管的生产构建。
- D1 保存设置、增量状态、审核记录和元数据；R2 保存共享文件与 Excel 导出。

公开发布必须使用通过完整验证的确定提交和已保存的 Sites 版本；保存版本不等于公开部署，部署前仍需明确批准。
