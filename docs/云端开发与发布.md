# 在 Codex 云端继续维护

## 三类云端内容不要混淆

1. **本 GitHub 仓库**保存源码、数据库迁移定义、空白审核模板和合成测试。公开仓库不是存放真实参赛资料、登录凭据或邮箱数据的地方。
2. **现有网站**仍运行在 Sites。D1 保存设置/审核等运行记录，R2 保存已收集文件和导出；源码上传不会搬迁、清空或备份这些数据。
3. **Codex 云环境**用于安装依赖、改代码和运行测试。环境的保存状态不替代 GitHub 提交，也不替代私有原件备份。

原网站地址：https://chem-e-car-registration.clever-morel-6302.chatgpt.site/

## 创建云端开发环境

按当前 OpenAI 官方流程，在 ChatGPT 网页或桌面端进入 **Settings → Codex Cloud → Environments → Create environment**，或在新任务选择 **Work in → Cloud → Select environment → Create environment**。

选择此 GitHub 仓库并确认授权，让 Codex 检查仓库和准备环境。建议使用 Node.js 24；必须满足 `package.json` 的最低版本。可以向环境设置助手提供以下安装/检查命令：

```bash
npm ci
npm run local:setup
npm run typecheck
npm test
```

`npm run local:setup` 使用随机值生成独立开发密码和密钥，保存在被 Git 忽略的 `.dev.vars`、`.local/` 中。需要登录本地预览时，由环境内的 `.local/本地登录信息.txt` 取得，不要贴进公开 issue、提交或构建日志。无需把生产站点密码复制到环境中。

检查设置报告和测试结果，解决缺失的权限/依赖后保存，并选择 **Publish**。看到 **Environment published** 才代表云环境已经就绪；GitHub 仓库存在并不自动完成此步骤。

之后从该已发布环境开始任务，例如：“检查并修改 EDP 第二轮 MOC 的证据定位，保留现有安全边界，运行相关测试，提交修改供我审阅。”

官方说明（以当前页面为准）：

- https://learn.chatgpt.com/docs/cloud
- https://learn.chatgpt.com/docs/environments/cloud-environments

## 在环境里运行和检查

```bash
npm run dev
npm run typecheck
npm test
```

默认开发服务监听 3000 端口，能否预览取决于云环境的端口/预览支持。`npm test` 包含构建，不需要为同一次检查重复执行 `npm run build`。原生核心的已编译 WASM 随源码提供；只有修改 C++ 实现并需要重新生成 WASM 时，才另外按 `docs/VSCode运行指南.md` 配置 Emscripten。

没有真实比赛原件仍可执行仓库中的合成回归测试；不能声称因此已经复验了全部真实学校。真实样例学习需要另行提供经过授权的私有输入。

## 更新源码与更新网站

在云端修改后检查差异、运行测试，再提交到 GitHub 或发起 PR。提交与推送不触发现有网站自动部署。

要更新原网站，需要具有原 Sites 项目权限的会话核对提交、同步源码、构建打包、保存版本并正式部署。保留 `.openai/hosting.json` 的原标识、DB/FILES 绑定和访问范围；不要把生产密钥写进 GitHub。

没有 Sites 授权的云端会话可以完成代码修改和测试，但不能宣称网站已上线。无需为了云端开发另建网站或迁移现有比赛数据库。

本仓库通过脱敏源码快照接入，保留目标仓库的初始提交；原 Sites 源码历史仍然独立。发布时应在原 Sites 授权流程中同步经过核对的修改，不要向任一远程强制推送，也不要把另一个仓库的提交历史直接覆盖过去。

## 本地空间与恢复

`node_modules/`、`dist/`、`.next/`、`.vinext/` 是可重建内容，可以在确认源码已上传后清理。重新克隆并运行 `npm ci` 后，可重新构建。

`.local/` 可能包含独立的开发数据库与登录信息，`work/`、`outputs/`、学习资料目录可能含唯一的真实文件。没有核实私有备份前，不应把这些目录当作缓存删除。GitHub 公开仓库中没有它们，因此不能从 GitHub 恢复它们。
