# 团队获奖证书生成模块设计

日期：2026-09-20

状态：设计已获用户批准，待书面规格复核；暂不实施、暂不公开发布

## 1. 背景与目标

现有赛事资料中心已经包含报名表、EDP、阿里邮箱、海报和视频等六个工作区，但仍需要人工排版团队获奖证书。操作者希望在网站中录入学校、奖项、指导教师和参赛队员后，直接得到与示例风格一致的横版 PDF，且同一届比赛的赛事名称、落款和公章不必每次重复设置。

本次改造的目标是新增“证书制作”工作区，第一阶段只制作团队奖项证书：每所学校或每支参赛队生成一张证书，列出全部指导教师和参赛队员。证书通过浏览器本地渲染并下载，人员姓名和单张证书内容不上传、不留历史记录；仅保存可复用的证书模板设置。

## 2. 范围与非目标

### 2.1 本次范围

- 新增第七个工作区“证书制作”；
- 首次制作前保存赛事名称、落款文字和公章图片，后续自动复用；
- 自动读取现有赛事资料中心保存的竞赛年份；
- 录入学校、奖项、指导教师、参赛队员和颁发月份；
- 在页面中实时预览 A4 横版证书；
- 一键生成并下载一所学校或一支参赛队的一页 PDF；
- 对模板缺失、名单超出容量、字体或公章加载失败等情况给出明确中文提示；
- 只允许已经登录的操作者查看和修改证书模板。

### 2.2 本次不做

- 不制作个人证书；
- 不从报名表自动导入学校或人员名单；
- 不做 Excel 批量导入、批量生成或证书压缩包下载；
- 不保存学校、奖项、指导教师、参赛队员或已生成证书的历史记录；
- 不生成证书编号、不提供电子签名或验真二维码；
- 不自动发送邮件或把证书写入阿里邮箱草稿；
- 不复刻示例中的真实公章，必须由已登录操作者上传正式图片；
- 不在本阶段公开发布。

## 3. 总体方案

采用“服务端保存模板、浏览器本地生成 PDF”的混合方案。

### 3.1 服务端职责

- D1 保存当前共享工作区唯一的证书模板文字设置；
- R2 保存当前模板使用的公章图片；
- 认证后提供模板读取、文字设置保存、公章上传和公章读取接口；
- 不接收单张证书的学校、奖项或人员名单。

### 3.2 浏览器职责

- 读取模板设置和竞赛年份；
- 解析操作者输入的姓名；
- 在高分辨率画布中排版完整证书；
- 把画布结果封装成单页 A4 横版 PDF；
- 使用本地下载保存 PDF，并在生成后保留当前表单，方便操作者核对或修改。

这种方案优先保证中文字体和复杂边框在最终 PDF 中的视觉一致性，同时避免把参赛人员名单发送到服务器。代价是 PDF 内文字不可搜索或选中，该限制在页面帮助文字中明确说明。

## 4. 页面结构与操作流程

### 4.1 工作区入口

在现有左侧导航末尾增加：

`07 证书制作`

工作区保持现有站点的深蓝、浅蓝和白色视觉体系，主操作顺序为：模板设置、证书内容、实时预览、生成下载。桌面端采用左侧表单、右侧预览；窄屏改为单列，先表单后预览。

### 4.2 首次模板设置

第一次进入且模板不完整时，页面顶部显示“请先完成证书模板设置”，生成按钮保持禁用。模板设置包含：

1. **赛事名称**：操作者手动录入一次，例如“中国大学生 Chem-E-Car® 竞赛暨 AIChE Chem-E-Car® 友谊赛”。正文中的年份由系统读取并放在赛事名称前，不要求在该字段重复录入年份。
2. **落款文字**：多行文本，由操作者按最终证书需要录入完整的组委会、协会或其他落款。系统保留换行并按右对齐排版，不自动改写文字。
3. **公章图片**：上传 PNG 或 JPEG。推荐使用透明背景 PNG；系统只保存当前模板的一张公章，新上传将替换旧图。

保存成功后，模板作为以后制作证书的默认模板自动加载。操作者可随时点击“编辑模板”修改；修改只影响之后生成的 PDF，不追溯修改已经下载的文件。

### 4.3 单张证书内容

模板保存后，日常制作区包含：

- **竞赛年份**：只读显示，读取现有 EDP 审核设置中的竞赛年份，不在证书工作区建立第二份年份设置；未设置时阻止生成，并提示操作者先到 EDP 审核设置选择年份。
- **学校/参赛队**：必填，保留操作者输入的正式全称。
- **奖项名称**：必填，例如“性能竞赛二等奖”。
- **指导教师**：必填，支持换行、空格、中文顿号、中文/英文逗号和分号分隔。
- **参赛队员**：必填，支持与指导教师相同的分隔方式。
- **颁发月份**：必填，默认当前年月，可由操作者调整，只显示到月份。

系统在解析姓名时去除首尾空白和空项，保持输入顺序，不擅自改写姓名，不自动去除同名人员；若存在重复项，以非阻塞警告提醒操作者检查。

### 4.4 预览与下载

- 任一字段变化后更新预览；
- 预览使用与 PDF 相同的排版引擎，只按比例缩小展示；
- 点击“生成并下载 PDF”前再次校验模板、竞赛年份和所有必填项；
- 下载文件名为 `学校名称-奖项名称-获奖证书.pdf`；
- 文件名中的 Windows 非法字符替换为安全连字符，但证书正文保留原文；
- 成功后显示“PDF 已生成并下载”，不向服务端提交证书内容。

## 5. 证书版式

### 5.1 页面与装饰

- 纸张：A4 横向，297 mm × 210 mm；
- 渲染分辨率：300 DPI，对应约 3508 × 2480 像素；
- 背景：白色；
- 边框：参考示例的金棕色双层纹样和四角装饰，但重新绘制为站点自有的简洁几何纹样，不直接复制截图像素；
- 标题：上方居中固定为“获奖证书”，使用金棕色大字，并配简洁分隔装饰；
- 主文字：深灰或近黑色；奖项名称使用金棕色并居中放大。

### 5.2 正文顺序

证书从上到下按以下顺序排版：

1. `〔学校/参赛队〕 参赛队：`
2. `在〔竞赛年份〕〔赛事名称〕中，表现卓越，并获得`
3. `〔奖项名称〕`
4. `特发此证，以资鼓励！`
5. `指导教师：〔全部指导教师〕`
6. `参赛队员：〔全部参赛队员〕`

正文标点、空格和换行由排版器统一处理，模板中的 `Chem-E-Car®` 等字符保持原样。第一版不开放标题和正文固定语句的自由编辑，避免误删关键内容。

### 5.3 落款、公章和日期

- 落款文字位于右下区域，并保留操作者在模板中录入的多行结构；
- 公章覆盖在落款区域的右下方，保持原图比例和透明度，不拉伸；
- 日期位于落款下方，格式固定为 `YYYY年M月`；
- 页面提供公章大小和位置的安全预设，不在第一版提供任意拖拽，保证每张证书一致。

### 5.4 名单容量与自适应

- 指导教师最多 5 人；参赛队员最多 15 人，与现有报名规则一致；
- 姓名按可用宽度自动换行，优先保持正常字号；
- 当行数增加时，先减小名单行间距，再在规定下限内小幅缩小名单字号；
- 奖项名称、赛事名称过长时采用相同的测量与缩放逻辑；
- 若达到最小字号后仍无法完整放入安全区域，禁止生成并明确指出哪个字段过长，绝不裁切、溢出边框或静默省略姓名。

## 6. 模板数据与接口

### 6.1 D1 模板记录

新增单例式模板记录，以当前认证工作区为归属，至少保存：

- `user_id`；
- `event_name`；
- `issuer_text`；
- `stamp_r2_key`；
- `stamp_filename`；
- `stamp_content_type`；
- `updated_at`。

现有共享工作区只产生一条当前模板记录。使用普通主键和现有数据库事务能力，不新增 hash、冻结 contract、baseline 或额外 gate。

### 6.2 R2 公章文件

公章存放在当前模板专属目录中，每次替换先写入一个新的对象键，再切换 D1 中的当前指针。上传新公章时：

1. 校验登录状态、文件大小、扩展名、MIME 和真实图片文件头；
2. 解码图片并校验尺寸；
3. 写入新的 R2 对象；
4. 更新 D1 模板元数据，使新对象成为当前公章；
5. D1 更新成功后清理上一张公章；若数据库更新失败，则清理本次新对象并继续使用上一张公章。

第一版接受 PNG 和 JPEG，单文件上限 5 MB，最短边不得小于 300 像素。读取接口需要登录，响应禁止公共缓存。

### 6.3 API 边界

计划提供以下受认证保护的能力：

- 读取当前证书模板；
- 保存赛事名称和落款文字；
- 上传或替换公章；
- 读取当前公章图片。

所有写接口沿用现有 CSRF/同源和会话校验。接口不接受学校、奖项、姓名、颁发月份或生成后的 PDF。

## 7. 浏览器 PDF 生成器

生成器拆分为三个清晰单元：

1. **输入规范化器**：解析姓名、校验数量和必填项，输出稳定的证书数据；
2. **证书排版器**：在固定 300 DPI 画布中绘制边框、标题、正文、名单、落款、公章和月份，同时返回溢出诊断；
3. **PDF 封装器**：将最终画布编码为高质量图像并写入单页 A4 横版 PDF，返回 `Blob` 供浏览器下载。

排版器和 PDF 封装器不依赖服务端。生成前等待所需字体和公章图片完成加载；任一资源失败时停止生成，不能导出缺字或无章的半成品。

为保证中文稳定，字体栈优先使用当前浏览器可用的正式中文字体，并在画布绘制前用 `document.fonts` 检查加载完成。若主要中文字体不可用，页面提示操作者而不是在无提示的情况下替换成不可控字体。

## 8. 状态与隐私

### 8.1 服务端保存

只保存赛事名称、落款文字、公章及其元数据。模板设置对已经登录的共享工作区操作者可见。

### 8.2 浏览器临时状态

学校、奖项、人员名单和颁发月份只存在于当前页面内存。页面刷新或关闭后不保证保留，且不写入 D1、R2、日志、分析事件或浏览器持久存储。

### 8.3 日志约束

前端和后端错误日志不得记录人员名单、完整表单内容或公章文件字节。错误信息只说明字段名称和失败类别。

## 9. 错误处理

- **模板未保存**：禁用生成按钮，定位到模板设置；
- **竞赛年份缺失**：提示到现有 EDP 审核设置中选择年份；
- **公章格式或尺寸不合格**：拒绝上传并说明允许格式、大小和最低尺寸；
- **公章替换失败**：保留旧公章和旧模板，不出现无章模板；
- **名单超过人数上限**：显示实测人数和允许上限；
- **文字溢出**：指出赛事名称、学校、奖项、指导教师或参赛队员中的具体超长字段；
- **字体加载失败**：停止生成并提示刷新或检查浏览器字体；
- **PDF 生成失败**：保留表单内容供重试，不生成空文件；
- **下载被浏览器拦截**：提供同一 Blob 的“再次下载”操作，不重新排版；
- **会话失效**：模板读写返回登录提示，但不把当前证书表单发送出去。

## 10. 测试与验收

### 10.1 模板设置

1. 未保存模板时不能生成证书。
2. 首次保存赛事名称、换行落款和公章后，刷新页面仍能正确加载。
3. 修改模板后只影响后续预览和下载。
4. 非图片、伪造扩展名、超过 5 MB 或尺寸不足的公章被拒绝。
5. 未登录请求不能读取或修改模板及公章。

### 10.2 表单与隐私

1. 换行、空格、顿号、逗号和分号均能正确分隔姓名并保持顺序。
2. 重复姓名给出警告但不擅自删除。
3. 5 名指导教师和 15 名参赛队员可以完整排版。
4. 超出人数上限或文字无法放入安全区域时阻止生成。
5. 生成过程中没有包含学校、奖项或姓名的网络请求，刷新后服务端也不存在证书历史。

### 10.3 版式与 PDF

1. 预览与下载使用同一排版数据和坐标，关键元素位置一致。
2. PDF 文件头正确，纸张为单页 A4 横向，月份格式为 `YYYY年M月`。
3. 所有指导教师和参赛队员均出现在 PDF 中，没有省略、截断或越界。
4. 公章保持比例并覆盖在落款的预设位置。
5. 文件名按 `学校名称-奖项名称-获奖证书.pdf` 生成并安全替换非法字符。
6. 在目标 Windows 浏览器中验证中文、`®`、英文连字符和换行正常。

### 10.4 站点回归

1. 导航从六个工作区扩展为七个工作区，原六个工作区顺序和功能不变。
2. 现有登录、报名表、EDP、邮箱、海报和视频测试继续通过。
3. 运行新增单元测试、接口测试、完整测试、Lint、构建和 `git diff --check`。
4. 在桌面和窄屏宽度进行本地界面检查。

## 11. 完成与发布边界

实施完成的定义是：模板可以保存并复用，目标人数范围内的单张团队证书可预览、生成和下载为合格 PDF，所有既有测试和新测试通过，且人员名单未离开浏览器。

本设计批准后仍需先编写实施计划，再按测试驱动方式开发。开发完成后只进行本地/ChatGPT 预览和验证；是否公开发布以及发布版本号需要用户另行明确确认。
