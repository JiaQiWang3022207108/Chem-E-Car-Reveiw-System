# Chem-E-Car 邮箱媒体采集、EDP 审核与控制台精简设计

日期：2026-09-01  
状态：已由用户确认总体路线，待用户审查本规格

## 1. 背景与目标

现有站点已经具备报名表、EDP、海报、视频、阿里邮箱和凡科一键采集功能，但海报与视频仍显示凡科入口，EDP 仅完成提交包文件数量/格式检查和回执生成，控制台也存在重复说明与信息密度过高的问题。

本次改造分为三个相互衔接的子系统：

1. 凡科只保留报名表和 EDP；海报与视频改由已登录的阿里邮箱浏览器会话采集。
2. 在 EDP 提交统计之外新增独立的 EDP 审核工作区，对提交成功的最新版 EDP 执行严格、证据驱动的逐项审核，并为每所学校生成一份包含两个工作表的 Excel。
3. 精简整站信息架构与视觉层级，减少重复卡片和长篇说明，同时保留较大字号、移动端适配和共享资料管理能力。

## 2. 设计原则

- **严格优先**：只有存在明确、可追溯证据时才自动给出“是”“否”或“不适用”；其他情况一律为“待人工确认”。
- **不把旧模板内容当标准**：模板中的天津大学、人员姓名、邮箱、已有“是/不适用”和旧日期属于示例残留，生成新文件时必须先清除对应变量单元格。
- **不自动发送或删除邮件**：助手只读取附件并写入本站共享资料库，不修改邮箱中的原邮件。
- **同校最新版**：以邮件收到时间或 EDP 提交时间为准，同校只保留时间最晚的有效版本；旧版标记为被替代而非误当最新版。
- **删除后可重新采集**：数据库中有历史采集记录但共享对象已被用户删除时，下次扫描必须重新下载，不能仅因“曾经处理过”而跳过。
- **可持续扩充**：审核规则和模板均有版本号。未来半年新增合格/不合格范本时，扩充规则并对需要的记录重新审核，不允许规则在无人审查的情况下自行修改。

## 3. 范围与非目标

### 3.1 本次范围

- 升级现有 Chrome 浏览器助手，使其可从已登录的阿里邮箱自动发现、分页扫描和收取海报/视频附件。
- 海报、视频页面移除所有凡科按钮、凡科日期设置和凡科问题提示。
- 复用现有共享媒体存储、待确认队列、200MB 分片上传、下载、单删和批量删除能力。
- 新增 EDP 审核队列、规则引擎、证据记录、人工确认、审核版本管理和 Excel 导出。
- 将用户提供的双工作表 Excel 作为不可变模板副本，生成每校独立审核文件。
- 调整导航、卡片、状态信息和配色，减少重复内容。

### 3.2 明确不在本次范围

- 不使用浏览器登录密码、Cookie 或阿里邮箱网页登录密码作为服务器凭据。
- 不在浏览器或电脑关闭时承诺继续使用网页登录会话采集。此时采集暂停，重新打开并保持登录后从检查点继续。
- 不在第一版使用生成式模型猜测全部 EDP 结论。
- 不在证据不足时把“未找到”直接判定为“不符合”。扫描型 PDF、文本提取质量不足或语义不明确时必须转人工确认。
- 不自动发送 EDP/报名回执，也不自动在阿里邮箱中删除、移动或标记原邮件。
- 不修改用户提供的原始 Excel 文件。

## 4. 总体架构

继续使用现有站点、Cloudflare Worker、D1、R2 和 Chrome 助手，不引入第二套独立服务。

### 4.1 浏览器助手

浏览器助手拆分为三个职责明确的适配器：

- `fanke-scraper`：仅处理报名表和 EDP。
- `alimail-draft`：继续负责逐封写入回执草稿，不发送。
- 新增 `alimail-collector`：负责识别已登录邮箱、自动进入收件箱、分页、读取邮件/附件元数据、下载附件并分片交给本站。

后台脚本负责寻找现有已登录标签页；找不到时自动打开收件箱或站点，但不会要求用户手动进入指定页面。页面结构未知、登录失效或附件信息无法确认时停止当前附件并返回中文错误，不继续盲目操作。

### 4.2 站点与共享存储

- 站点页面保存海报和视频各自的起始日期、频率、启用状态与扫描进度。
- 浏览器助手通过已登录站点页的 `site-bridge` 调用受会话保护的上传 API，避免把共享密码或会话令牌写入扩展。
- 文件使用现有 8MB 分片接口上传到 R2；D1 保存学校、类型、邮件指纹、收到时间、文件大小、对象键和状态。
- 对象存在性参与增量判定：历史指纹存在但 R2/共享记录缺失时，重新排队上传。

### 4.3 EDP 审核引擎

- 只有已经通过 EDP 提交包数量与格式检查的记录才创建审核任务。
- 同一学校同一轮次出现更新版本时，旧审核任务标记为 `superseded`，最新版重新审核。
- 审核引擎从 R2 读取 ZIP，识别中文版 EDP、英文版 EDP、增补文件以及第 2–5 次提交所需的 MOC，提取各 PDF 的文本、页码和短证据片段。
- 每一项规则输出状态、证据、建议意见和规则版本。证据不足的状态为 `needs_human`，界面显示“待人工确认”。
- 人工修改必须记录修改前结果、修改后结果、操作者和时间，确保审核结论可追溯。

## 5. 阿里邮箱媒体采集

### 5.1 用户流程

1. 用户安装或升级浏览器助手，在同一浏览器中登录阿里邮箱和本站。
2. 用户分别在海报、视频栏目设置起始日期、扫描频率和是否启用。
3. 助手到期后自动寻找已登录邮箱，进入收件箱并从检查点向后扫描；无需用户刷新或停留在某一页。
4. 附件被分类为海报、视频或待确认，符合规则的文件以同校最新版写入共享资料库。
5. 页面实时显示本轮扫描进度、保存数量、跳过数量、待确认数量和错误；完成后自动刷新清单。

### 5.2 格式与大小

- 海报：`.ai`、`.jpg`、`.jpeg`、`.zip`、`.7z`、`.rar`。
- 视频：`.mp4`、`.zip`、`.7z`、`.rar`。
- 单文件上限：200MB。
- 压缩包不能仅凭扩展名判断类型。必须结合邮件主题、附件名、附近字段和学校名称；仍有歧义时进入待确认队列。

### 5.3 分类顺序

1. 明确 MIME 类型和扩展名。
2. 附件名中的“海报/poster”或“视频/宣传片/video/mp4”。
3. 邮件主题和正文标题中的资料类型。
4. 学校名称从附件名、主题、发件人显示名及已有学校清单中归一化匹配。
5. 类型或学校任一项不确定时不得自动归档。

校区必须保留为不同学校，例如中国石油大学（北京）、中国石油大学（北京）克拉玛依校区和中国石油大学（华东）不能合并。

### 5.4 增量、覆盖与删除

- 邮件指纹由稳定邮件标识、附件序号、附件名、大小和收到时间组合生成。
- 已有相同指纹且共享对象仍存在时跳过。
- 同校新附件时间晚于当前版本时覆盖当前展示版本；旧对象按既有清理策略移除。
- 用户删除本站文件后，下一次扫描发现共享对象不存在，重新采集该附件。
- 删除本站文件不影响阿里邮箱原邮件。

## 6. EDP 严格审核

### 6.1 审核状态

每个检查项只能是以下四种状态之一：

- `yes`：明确证据支持符合。
- `no`：明确证据支持不符合，或规则要求的材料明确缺失。
- `not_applicable`：EDP 明确说明该项目不适用，且上下文一致。
- `needs_human`：证据不足、PDF 无可用文本、存在冲突、规则尚未覆盖或适用性无法可靠判断。

“没有搜索到关键词”本身不能作为 `no`。只有规则定义了完整搜索范围且文档文本质量达标，或存在明确矛盾时，才允许自动判否。

### 6.2 审核规则结构

每项规则至少包含：

- 稳定规则编号和规则版本。
- 对应模板工作表、状态单元格和意见单元格。
- 适用文件范围（中文 EDP、英文 EDP、增补文件、MOC）。
- 正向证据条件、否定证据条件、适用性条件和所需文本质量。
- 状态建议、中文意见模板、证据页码和短摘录。
- 是否允许自动形成结论；未达到阈值时强制 `needs_human`。

第一版只自动处理有客观、可重复证据的项目。用户后续提供合格与不合格范本时，新增或收紧规则，并提升规则版本。旧审核结果保留原规则版本，可由用户选择“按最新规则重新审核”。

### 6.3 审核任务流程

1. 最新合格 EDP 入队。
2. 解压并验证 PDF 角色；异常转为审核错误，不改变原 EDP 提交回执。
3. 提取文本、页码、文档语言和文本质量。
4. 逐条执行规则，保存证据和建议意见。
5. 页面按“自动通过、自动不通过、待人工确认”分组展示。
6. 用户可查看原 PDF、证据页码、建议结论和意见，并逐项确认或修改。
7. 任意时刻可以下载带“待人工确认”标记的草稿 Excel；所有待确认项处理完后才能确认并生成正式 Excel。

### 6.4 总体结论

- 存在任一 `no`：总体为“不通过审查”，总体意见汇总主要问题。
- 不存在 `no` 但存在 `needs_human`：总体为“待人工确认”，不能显示为通过。
- 全部项目为 `yes` 或经证据支持的 `not_applicable`，且用户完成最终确认：总体为“通过审查”。

## 7. Excel 模板与单元格映射

模板保留两个原工作表名称：`1) EDP Cover Page` 与 `2) EDP Evaluation`。生成器直接复制原始工作簿包并只修改已定义单元格，保留合并单元格、行高、列宽、字体、边框和打印布局。

### 7.1 工作表 1：EDP Cover Page

生成前清除旧示例值，再按下列映射填写：

| 目标 | 单元格 | 来源 |
| --- | --- | --- |
| 竞赛年份标题 | `A1:E1` | EDP 审核设置中的竞赛年份 |
| 学校名称 | `E4` | 当前审核任务学校 |
| 作品名称 | `E5` | 最新报名表或 EDP 明确字段；否则“待人工确认” |
| 指导教师 | `E6` | 最新报名表或 EDP 明确字段；否则“待人工确认” |
| 指导教师邮箱 | `E7` | 最新报名表有效邮箱；否则“待人工确认” |
| 安全与规则审查人 | `E8` | 用户保存的审核设置；未设置则留空 |
| 审查人邮箱 | `E9` | 用户保存的审核设置；未设置则留空 |
| 专家委员 | `E10` | 用户保存的审核设置；未设置则留空 |
| 专家委员邮箱 | `E11` | 用户保存的审核设置；未设置则留空 |

| 审查人 | `C16` | 用户保存的审核人姓名 |
| 审查结论 | `D16:E16` | 通过、不通过或待人工确认 |
| 安全规则核查页至安全规则 | `C20:C24` | 对应审核状态的中文显示值 |

固定说明文字和检查项名称保持不变。任何未配置人员信息不得沿用模板中的旧姓名或旧邮箱。

### 7.2 工作表 2：EDP Evaluation

固定章节标题和 C 列检查项文字保持不变。以下行的 B 列填写审核状态，D 列填写意见和证据摘要：

`5, 6, 8–13, 15–16, 18–27, 29–32, 34, 36–37, 39–41, 43–44`。

状态显示限定为“是”“否”“不适用”“待人工确认”。“待人工确认”的 D 列必须说明原因，例如“PDF 为扫描图像，当前无法可靠确认签字内容”，而不是留空。

### 7.3 草稿与正式版

- 草稿文件名：`第N次EDP审核意见__学校名称__草稿.xlsx`。
- 正式文件名：`第N次EDP审核意见__学校名称.xlsx`。
- 每次导出记录模板版本、规则版本、EDP 提交标识和生成时间。
- 原始模板的文件哈希在生成前后保持不变。

## 8. 数据模型

优先复用现有媒体和邮箱表，新建审核相关表；迁移必须保留现有数据。

### 8.1 邮箱媒体扫描

- `mail_media_scan_settings`：用户、媒体类型、起始日期、频率、启用状态、最近扫描时间、下次扫描时间。
- `mail_media_scan_checkpoints`：邮箱会话/文件夹标识、最后稳定邮件键、扫描状态和错误。
- `mail_media_seen_attachments`：附件指纹、类型、学校、收到时间、共享对象状态和最后确认时间。
- 继续复用 `mail_media_candidates` 与 `shared_media_assets`。

### 8.2 EDP 审核

- `edp_review_settings`：竞赛年份、审核人/专家委员姓名和邮箱、当前模板版本。
- `edp_review_jobs`：学校、轮次、EDP 提交标识、规则版本、模板版本、状态、总体结论和被替代关系。
- `edp_review_items`：任务、规则编号、模板行、自动状态、最终状态、建议意见、最终意见、证据摘要、文档名、页码和人工修改信息。
- `edp_review_exports`：任务、草稿/正式类型、R2 对象键、文件名、生成时间和生成时使用的规则版本。

所有表按当前共享登录用户分区，并建立学校、提交时间、任务状态和更新时间索引。

## 9. API 与扩展消息边界

### 9.1 邮箱媒体

- 获取/保存海报和视频扫描设置。
- 创建扫描会话并验证站点登录状态。
- 分批提交邮件与附件元数据。
- 初始化、上传、完成或取消分片附件。
- 查询附件是否仍在共享资料库，用于删除后的重新采集。
- 提交扫描进度、结束状态和可读错误。

扩展消息只允许来自本站和阿里邮箱白名单来源；所有字段有长度、类型、扩展名和大小限制。

### 9.2 EDP 审核

- 获取审核设置和保存审核人员信息。
- 列出审核任务与逐项结果。
- 启动或按最新规则重新审核指定学校。
- 保存人工确认/修改。
- 生成和下载草稿 Excel。
- 所有待确认项完成后确认总体结论并生成正式 Excel。
- 删除审核导出文件时保留审核记录；重新导出可以恢复文件。

## 10. 页面与视觉设计

左侧导航调整为：

1. 报名表统计
2. EDP 提交统计
3. EDP 审核
4. 阿里邮箱连接
5. 海报收集
6. 视频收集

### 10.1 信息精简

- EDP 提交页只保留提交包校验、回执、文件管理和凡科采集，不显示审核意见。
- EDP 审核页集中显示审核进度、待人工确认、问题项、证据和 Excel 下载。
- 阿里邮箱连接页保留登录/助手状态、扫描设置、待确认附件和错误；原始邮件清单移入可折叠的“高级查看”。
- 海报和视频页只显示邮箱扫描状态、手动补录、最新文件清单和批量删除，不再显示凡科控制台。
- 重复的“共享模式”“规则说明”“文件保存在哪里”等长卡片合并为一条可折叠帮助信息。

### 10.2 视觉语言

- 背景使用柔和的浅灰蓝，主色为沉稳蓝，成功、警告和错误仅用于状态，不大面积铺色。
- 保留清晰的大字号和较高字重，但通过留白、字号和色阶建立层级，避免每段文字都同样粗重。
- 卡片边框变浅、阴影减弱、圆角统一；主操作按钮每个区域最多一个。
- 桌面端使用紧凑双栏，手机端改为单栏，按钮和表单保持足够触控高度。
- 状态不能只依赖颜色，必须同时显示文字或图标。

## 11. 安全与错误处理

- 浏览器助手不读取、保存或上传阿里邮箱密码和 Cookie。
- 扫描只读取收件箱和附件，不发送、删除、移动或标记邮件。
- 附件名清洗路径字符，服务端再次验证扩展名、大小和分片完整性。
- 上传失败保留可恢复会话并重试；多次失败进入问题清单，不覆盖现有有效文件。
- AliMail 页面变化、登录失效或目标控件不可识别时停止并给出中文提示，不继续点击未知元素。
- PDF 解压限制文件数量、单文件大小和总解压大小，防止压缩炸弹。
- 审核证据只保存必要的短摘录和页码；原 PDF 保持在原 EDP 对象中。
- 正式 Excel 只有在用户完成所有人工确认并明确点击确认后生成。

## 12. 测试与验收标准

所有行为变更采用测试先行。

### 12.1 邮箱媒体采集

- 海报/视频页面和助手不再存在凡科启动入口，报名表/EDP 凡科采集不受影响。
- 助手能从任意已登录阿里邮箱页面自动进入收件箱并分页，不要求手动刷新。
- 起始日期之前的邮件不下载；海报和视频分别遵守各自设置。
- 文件分类、校区归一化、同校最新版、200MB 限制、分片重试和待确认路径均有测试。
- 已保存对象跳过；用户删除对象后同一附件能够重新采集。
- 登录失效或页面未知时产生明确错误，且不会误归档附件。

### 12.2 EDP 审核

- 只有最新的合格 EDP 创建有效审核任务；新版本使旧任务失效并重新审核。
- 没有充分证据时必须为“待人工确认”，不能误判为通过或不适用。
- 明确证据、明确矛盾、低文本质量、扫描型 PDF 和规则冲突分别有回归测试。
- 人工修改保留审计记录，总体结论按严格规则计算。
- EDP 提交回执与审核意见相互独立，审核失败不能改写已生成的提交回执。

### 12.3 Excel

- 生成文件始终包含两个原工作表名称和原合并区域。
- 所有旧示例人员、邮箱、日期和审核状态均被清除或按当前任务重写。
- 指定状态单元格和意见单元格填写正确，待人工确认原因可见。
- 草稿允许待确认；正式版在仍有待确认项时拒绝生成。
- 生成文件可重新打开，关键单元格无公式错误，原模板哈希不变，并完成两个工作表的视觉渲染检查。

### 12.4 发布门槛

- 完整测试、生产构建、ESLint 和差异检查全部通过。
- 浏览器助手打包版本号更新，安装说明同步更新。
- 先保存站点版本并核对部署状态；公开发布前使用明确批准的版本。

## 13. 实施顺序

1. 先完成数据迁移、API 边界和失败测试。
2. 移除海报/视频凡科路径并实现 AliMail 媒体扫描助手。
3. 实现 EDP 审核数据模型、证据引擎和人工确认界面。
4. 实现不可变模板复制与双工作表 Excel 生成。
5. 精简页面和调整视觉样式。
6. 运行完整验证、打包新助手、保存站点版本并按授权发布。

该顺序允许每个子系统独立验证，也保证第一版审核在规则不足时保持保守而不是输出未经证实的结论。
